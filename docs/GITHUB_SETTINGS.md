# Настройки GitHub

Этот файл описывает, как человек проверяет внешние настройки репозитория. Границы работы ИИ закреплены в [AGENTS.md](../AGENTS.md). YAML в checkout подтверждает триггеры, но активные rulesets, обязательные статусы, роли и права находятся в GitHub.

- Открой в настройках репозитория список Rulesets. Проверь охваченные ветки, обязательные статусы, способ слияния, правила обхода и список затронутых пользователей. Для разрешённого релиза сверяй настройки с [workflow](RELEASING.md#триггеры-в-репозитории).
- `.github/rulesets/protect-main.json` и `protect-release-tags.json`, `.github/labeler.yml`, `.github/scripts/audit-gate.mjs` и конфиги Release Please унаследованы от прежнего процесса. Перед применением шаблона сопоставь его требования с workflow и фактическими именами статусов. Требование отсутствующего статуса может блокировать слияние.
- Права запуска workflow, доступ к GHCR, настройки окружений и секретов проверяй в разрешённом интерфейсе. Для аудита достаточно чтения настроек. Любые изменения выполняет человек.
