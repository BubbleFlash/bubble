# Bubble — передача контекста

## Сбор на сервер

- Авторизованным пользователям в правой колонке показывается цель Boosty «На оплату серверов на год», полученная по идентификатору 842291. Сервер кэширует успешный ответ на 15 секунд, клиент обновляет данные с тем же интервалом. Клиент показывает название, сумму, шкалу в акцентном цвете и ссылку поддержки. При недоступности данных выводится сообщение, ссылка остаётся доступной.
- В мобильном меню сбор отображается после навигации. Кнопка поддержки использует акцентный цвет пользователя, активный пункт и полоса прокрутки оформлены в стиле Aero.
- Используется публичный внутренний маршрут Boosty, его формат может измениться. Проверены ответ Boosty, обработка ошибок и интерфейс с имитацией API.

## Управление группами

- Окно управления сохраняет высоту при переключении вкладок. Длинное содержимое прокручивается внутри окна, вкладки используют оформление ленты.
- Под описанием группы показан список управляющих с именем и подписью или ролью. Владелец может изменить подпись, скрыть человека из списка и вернуть его обратно через панель управления.

- Шестерёнка в шапке группы открывает адаптивное Aero-окно с правами, участниками и управляющими. Владелец назначает администраторов и редакторов, снимает роли и выбирает, кто может публиковать записи и репосты, редактировать и удалять записи, менять название, описание и аватар. Администраторы видят настройки прав, меняют оформление при разрешённом уровне доступа и могут исключать обычных участников.
- По умолчанию публикуют все участники. Участники редактируют и удаляют свои записи, редакторы и администраторы могут изменять чужие. Оформление доступно администраторам и владельцу. API проверяет права независимо от видимости кнопок в интерфейсе. Редактор записи меняет текст, фотографии и музыку.
- Владение передаётся действующему участнику после ввода адреса группы. Бывший владелец становится участником. Поле `Community.creator` определяет текущего владельца, роли управляющих привязаны к ID членства. Передача, назначение ролей, изменение прав и исключение участника используют версию состояния доступа. Для существующих групп применяются значения по умолчанию без миграции.
- Проверены полномочия через API на изолированной MongoDB, включая конкуренцию передачи с выходом участника. Сценарии панели, оформления и редактирования записей проверены в Chrome на 1440, 390 и 320 px с локальным API и MongoDB.

## Музыкальный интерфейс после слияния

- Кнопки плеера, загрузки и выбора вложений привязаны к общим Aero-контролам. При открытой очереди на узких экранах предусмотрено место для кнопок окна выбора.
- В Chrome с имитацией API проверены рамки на 390/768/1440 px, переход на 1100/1101 px, три режима плеера, прокрутка очереди, перетаскивание и возврат позиции после перезагрузки. Проверены источники воспроизведения, синхронизация библиотеки, скачивание, видимость библиотеки и цепочка загрузки WAV с ошибкой и повтором.

## Персональное оформление (ветка feature/custom-UI-settings)

- Страница `/settings` доступна из левого меню, мобильной панели и бургер-меню. В ней можно загрузить PNG/JPEG/WebP/GIF, выбрать текущий стандартный фон, настроить основной и акцентный цвета и включить статическое или пульсирующее свечение аватара. Для каждого цвета есть палитра и произвольное значение, для свечения — пять уровней силы. Изменения применяются после сохранения.
- `PATCH /users/me/appearance` атомарно обновляет переданные поля. Приватные фон и палитра входят в данные владельца при авторизации и восстановлении сеанса. Рамка приходит вместе с аватаром в профиле, ленте, комментариях, поиске, друзьях, сообщениях, публичном обзоре и жалобах. Для существующих аккаунтов используются стандартные настройки без заполнения старых записей. Фон использует действующий серверный маршрут загрузки изображений.
- Общие токены Aero применяют палитру на всех маршрутах авторизованной оболочки. Настройки пульсации учитывают `prefers-reduced-motion`.
- Проверены сборки, TypeScript, ESLint изменённых файлов и Chrome с имитацией API на 1440/390/320 px. API-тесты проверяют валидацию, частичное обновление и состав публичного профиля. Четыре теста прямой загрузки ожидают маршруты, отсутствующие в исходной версии ветки. Реальная загрузка и запись в MongoDB отдельно не проверялись.

## Оформление профиля и черновик настроек

- При уходе со страницы настроек открывается окно с вариантами сохранить и перейти, уйти без сохранения или остаться. При закрытии или перезагрузке вкладки используется системное предупреждение браузера. Локальный фон применяется к оболочке сразу после выбора файла.
- При посещении чужого профиля оболочка использует сохранённые фон, палитру и шрифт владельца. Если владелец использует стандартное оформление или ограничил показ в «Приватности» и посетитель не входит в выбранную аудиторию, сохраняется оформление посетителя. Варианты видимости — все пользователи, только взаимные друзья или только владелец. API включает тему профиля в ответ только при разрешённом показе.

## Шрифт сайта

- Во вкладке «Визуал» можно выбрать системный шрифт или загрузить WOFF2, WOFF, TTF либо OTF до 2 МБ. Выбор сохраняется в оформлении аккаунта. Загруженные шрифты используют существующее файловое хранилище. При ошибке загрузки сохранённого шрифта применяется стандартный.

## Мобильная навигация

- Мобильная панель авторизованного пользователя содержит «Профиль», «Ленту», «Сообщения», «События» и кнопку «Меню» справа. Друзья, группы, музыка и настройки доступны в выдвижном меню.

## Разделы настроек

- Вкладки «Визуал», «Приватность» и «Уведомления» используют оформление вкладок ленты. По умолчанию открывается «Визуал» с оформлением и мастерской, прямые ссылки на остальные вкладки используют `?tab=privacy` и `?tab=notifications`.
- Видимость списка друзей сохраняется автоматически во вкладке «Приватность». Вкладка «Уведомления» содержит настройки звука и push. Страницы друзей и событий показывают списки и заявки.
- Видимость музыкальной библиотеки в профиле настраивается в «Приватности» и сохраняется сразу. Варианты — все пользователи, взаимные друзья или только владелец. Настройка относится к библиотеке профиля, общий каталог доступен по прежним правилам.
- Основная прокрутка Aero-оболочки принадлежит документу. Верхняя рамка, шапка и баннер подтверждения почты закреплены, а история переписки прокручивается внутри диалога.

## Профили и отображаемые ники

- Владелец профиля может публиковать записи через тот же редактор, что и в ленте. В режиме редактирования профиля поле отображаемого ника заменяет заголовок.
- Регистрационный `username` служит ID для ссылок. Отдельное поле `displayName` поддерживает Unicode и обновляется через `PATCH /users/me`. Для старых аккаунтов без этого поля видимым ником служит ID. Поиск по людям и друзьям принимает оба значения.
- Профиль периодически обновляет онлайн-статус. Посты получают снимок состояния автора при загрузке. API запрашивает статусы пачкой у Socket.IO через внутренний маршрут `/internal/online`. Открытая авторизованная страница показывает владельцу «Онлайн» в собственном профиле и на своих постах даже без Socket.IO. Для остальных авторов при недоступности сервиса отображается «Офлайн».

## Мастерская фонов

- В настройках из раздела «Фон сайта» открывается Aero-окно мастерской. Плитки сразу показывают фон на сайте, кнопка сохранения закрепляет его в аккаунте. Избранные фоны доступны в отдельном блоке настроек с теми же кнопками лайка, избранного и жалобы, что и в каталоге. Каталог перелистывается по 15 фонов, избранное — по 8, с переходом по номерам страниц, а окно мастерской сохраняет высоту при смене страницы.
- Каталог поддерживает публикацию PNG/JPEG/WebP/GIF через отдельное окно с названием фона, поиск по названию, сортировку по лайкам и новизне, а также фильтр по опубликованным фонам взаимных друзей и фонам из каталога, установленным у них сейчас. Личные файлы появляются в каталоге при отдельной публикации через мастерскую.
- Маршруты `/wallpapers` используют существующее хранилище изображений. Уникальные реакции привязаны к аккаунту. Жалобы используют те же причины, что жалобы на посты, и хранятся в коллекции `WallpaperReport` для дальнейшего подключения к админке. Файл каталога сохраняется при смене фона пользователем.
- Проверены целевые API-тесты с подменой MongoDB и хранилища и сценарии в Chrome на 1440/390/320 px с имитацией API.

## Backend взаимных подписок (локальная работа)

- Существующий Socket.IO доставляет сообщения и уведомления. При пересечении события с GET открытой переписки клиент отменяет устаревший запрос и сверяет диалог с API. MongoDB подтверждает переход в прочитанное условной записью. В открытых уведомлениях клиент учитывает каждое новое непрочитанное событие.
- Резервные интервалы при подключённом Socket.IO для переписки, списка диалогов и счётчика сообщений составляют 60/120/180 с, при отключённом — 15/45/30 с. Открытые уведомления, их счётчик и количества на собственной странице друзей проверяются раз в 30 с. Лента обновляется при открытии, возврате на вкладку и повторном выборе в навигации. Производительность запроса количеств на больших данных не измерена.
- После reload личные запросы и соединение ожидают подтверждения сеанса. Браузер повторяет временно неудачное восстановление сеанса и учитывает заголовок `Retry-After`. Старый признак гостя `0` перепроверяется один раз. Доставка сообщений, заявок и уведомлений, reconnect и загрузка ленты проверены в локальном Chrome с двумя аккаунтами, реальными API, Socket.IO и временной MongoDB. Конфигурация и задержки production не проверялись.

- Вкладки собственной страницы друзей показывают общие количества из `/users/me/relationships/counts`. Настройка приватности перенесена в четвёртую вкладку с шестерёнкой; на чужой странице элементы управления отсутствуют. Локальная сетка выравнивает высоту вкладок. Проверены 23 целевых backend-теста (включая временную MongoDB) и Chrome с имитацией API на 1440/390/320 px, ошибка сохранения и повтор.

- В профиле находится компактный блок последних шести друзей. Собственная страница `/friends` содержит друзей, односторонние исходящие и входящие заявки и настройку приватности; `/friends/:username` показывает только разрешённый список друзей. Сортировка друзей использует время возникновения взаимности; старый курсор такого списка нужно сбросить. Подписки и старый POST сохранены.
- Серверная приватность друзей: `everyone` / `friends` / `only_me`; для аккаунтов без настройки согласовано значение `everyone` без миграции. Владелец меняет настройку на странице друзей. Счётчик и список проверяют доступ на сервере; подписки и публикации сохранены. Детали: `docs/RELATIONSHIPS_API.md`.
- На ветке `friends_system` добавлены идемпотентные PUT/DELETE подписки, обратный флаг `followsMe` в профиле и авторизованный список собственных отношений с поиском и курсором. Прежний POST-переключатель сохранён. Контракты и ограничения: `docs/RELATIONSHIPS_API.md`.
- Дружба вычисляется по двум Follow-записям. Новый список скрывает административно заблокированных пользователей, как поиск. Уникальный индекс и конкурентность проверены на отдельной временной локальной тестовой MongoDB; наличие индекса и дубликатов в целевой БД не проверялось. Миграции и операции с production не выполнялись.
- Проверены 42 целевых backend-теста, включая интеграцию с временной MongoDB, typecheck и сборки API/web. Chrome с имитацией API: 1440 и 390 px, компактный блок, страница друзей, приватность, поиск, пагинация и четыре состояния отношений. Полный сценарий смены аккаунта, реальные авторизация и API в браузере, производительность на больших данных не проверены.

## Реализовано локально

- Ссылки в постах, комментариях и сообщениях кликабельны; для первой ссылки в тексте показывается превью, а YouTube открывается во встроенном плеере. Метаданные обычных сайтов запрашиваются через авторизованный `/link-preview`: только HTTP(S), публичные IPv4-адреса с фиксацией адреса соединения и проверкой перенаправлений, лимиты времени и размера. Для недоступных сайтов остаётся карточка домена; IPv6-only сайты и изображения более 150 КБ не загружаются.

- Посты и личные сообщения поддерживают до 10 изображений и общий модальный просмотрщик. Изображения сообщений загружаются отдельно от публичных `/uploads`, доступ к ссылке проверяется по автору или участию в переписке; временные ссылки действуют 120 секунд. Закрытость S3-бакета и сквозная работа с реальным хранилищем ещё не проверены. Автоматическая очистка неиспользованных загрузок сообщений пока не реализована.

- В профиле выводятся три последних трека; «Открыть» ведёт в собственный раздел музыки либо в `/u/:username/music` с постраничной загрузкой видимой библиотеки. На странице `/music` по умолчанию открыта «Моя библиотека».

- Для новых загрузок музыки браузер считывает длительность из локального файла и передаёт её при подтверждении загрузки; если метаданные недоступны, загрузка продолжается без длительности. Ранее загруженные треки автоматически не обновляются. Значение поступает от клиента и не является проверенными сервером метаданными.
- В каталоге музыки добавлено скачивание через авторизованный API и временную ссылку хранилища с заголовком сохранения файла; работа с реальным хранилищем ещё не проверена.
- Плеер хранит источник текущей очереди: каталог, библиотека, профиль, публикация или сообщение. Подсветка и состояние кнопки соответствуют источнику, в том числе при паузе; переключение источника для текущего трека не перезапускает аудио.
- В плеере доступно управление принадлежностью текущего трека библиотеке; в полном режиме также доступно скачивание. Для актуального состояния используется авторизованный GET `/music/:id/library`.
- Общая строка музыки используется в каталоге, библиотеке, профиле, публикациях и сообщениях. Статусы принадлежности для списка запрашиваются пакетно через авторизованный POST `/music/library/status`; запрос ограничен 100 идентификаторами и возвращает только принадлежность текущему пользователю.

- Общая светлая Aero-оболочка обычных маршрутов: стеклянная рамка, декоративные кнопки окна, синяя шапка, единый фон, панели и системные кнопки. Авторизация сохраняет отдельную компоновку с той же палитрой.
- Основное содержимое Aero-окна прокручивается нативно внутри `.shell`. Заголовок, баннер подтверждения и мобильная панель находятся вне этой области. Рамка фиксирована, а история сообщений сохраняет собственную прокрутку. Граница содержимого задаётся CSS-компоновкой окна без пересчёта обрезки в JavaScript.
- Единая конфигурация меню: Профиль, Лента, Поиск, Сообщения, Группы, События. Маршрут событий остаётся `/notifications`. Desktop, нижняя панель и бургер-меню используют одну конфигурацию; гостям доступны обзор, регистрация и вход.
- PNG-иконки навигации переиспользуются во всех вариантах меню. Общий компонент бренда использует новый логотип, сохранено название Bubble; favicon и существующие PWA-иконки обновлены.

## Репосты публикаций и комментариев

- В редакторе публикации доступна видимость «Только друзья». Доступ получают пользователи с взаимной подпиской. Существующие записи «Только я» остаются доступны автору.
- Владелец сообщества может изменить название, описание и аватар. Записи сообщества показывают его название и аватар, а ссылку на автора — над действиями.
- Страница групп открывается на вкладке «Подписки», рядом доступны «Все группы» и «Мои» с группами владельца. В репосте списки групп и диалогов содержат аватары, поиск диалога встроен в поле выбора.

- Кнопка «Поделиться» открывает модальное Aero-окно с необязательной подписью. Можно опубликовать репост в своём профиле, в сообществе с действующим членством или отправить его в личные сообщения. Ссылка на цитату переводит к комментарию на странице исходной записи.
- `POST /posts/reposts` создаёт отдельную запись с собственными реакциями и обсуждением. MongoDB хранит ссылку на источник и идентификаторы предков. По ним API считает репосты публикаций и сообщений для каждого предка, а для оригинала — уникальные аккаунты с лайком на нём или на любом сохранившемся репосте.
- Карточки загружаются с учётом доступа текущего пользователя и показывают заглушку при удалении или ограничении доступа. После трёх уровней вложенности показывается ссылка на следующую запись. Для записи в профиле доступен режим «Только я». Старые записи без поля видимости считаются публичными. Файловое хранилище по-прежнему использует адреса загрузок, которые выдаются в данных записи только получателям с доступом к её карточке.
- Публиковать и покупать платные записи больше нельзя. Старые записи с ценой скрыты из ленты, профилей, сообществ, поиска и репостов. Их содержимое и история покупок сохранены в БД.
- Сообщения хранят ссылку на источник. Событие Socket.IO содержит признак репоста, а карточка загружается через API с правами участника. Автор исходной записи получает уведомление. При отправке в личные сообщения уведомление ведёт к оригиналу и не содержит данных переписки.
- Интеграционные проверки запускаются с `BUBBLE_REPOST_TEST_MONGO_PORT` и используют отдельную временную базу на локальной MongoDB.

Общий компонент используется лентой, профилем, поиском, сообществами и страницей записи.
