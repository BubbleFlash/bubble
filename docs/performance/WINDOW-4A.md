# Этап 4A · окно карточек авторизованной ленты

## Архитектура

- `PostList` передаёт загруженные записи окну только на вкладках «Подписки» и «Все записи». Окно использует штатный scroller документа или вложенную прокрутку Aero в Firefox Android. Курсор и кнопка догрузки работают в конце полного оценочного списка. DTO остаются в TanStack Query.
- `FeedGeometry` хранит префиксные суммы высот. Найти строку по смещению, прочитать префикс и обновить одну высоту можно за O(log n). Перестроение происходит при изменении последовательности ID или сбросе геометрии по ширине/шрифту. Обновление DTO выполняет сверку ID и сохраняет геометрию, когда порядок прежний. Один ResizeObserver принимает размеры только смонтированных строк. После измерения строки React обновляет окно, когда изменился состав, а смещения корректируются отдельно.
- Окно держит запас около одного viewport до и после видимой области с гистерезисом. Пустые участки — проставки между смонтированными карточками в нормальном потоке. Ключи строк — ID публикаций. Переходы клавишей Tab через границу окна подмонтируют соседнюю публикацию. При нижней границе новый реальный размер карточек сохраняет привязку к концу списка.
- Состояние живёт на уровне аккаунта. Сохраняются черновики комментариев и редактора, включая изображения и адресата ответа, раскрытие текста и обсуждений, выбранный слайд публикации и раскрытие 18+. Для пустого состояния запись удаляется при размонтировании. Явно удерживаются текущий фокус и выделение, открытые окна, незавершённая отправка и последнее активированное видео в iframe. Глобальный аудиоплеер хранит своё состояние над маршрутами. При смене аккаунта освобождаются принадлежащие черновикам object URL.
- Восстановление позиции использует ID карточки и смещение, ключ истории и вкладку. Поддержаны Back после публикации или профиля и ссылка возврата с публикации. Высоты хранятся отдельно для каждой вкладки, до 4 096 измерений на вкладку, с очисткой по ширине/шрифту и удалением высот записей, которых больше нет в наборе. История хранит до 16 входов. Настоящие пользовательские черновики сохраняются на время сеанса.
- `VITE_FEED_WINDOW=0` при сборке выбирает полную ленту. Её и диагностический вариант можно прогонять тем же стендом. Текущий кандидат измеряется с `BUBBLE_PERF_WINDOW=1`. Смонтированные строки учитываются отдельно от числа полученных DTO.

Исходники и штатная точка входа. [FeedWindow](../../apps/web/src/components/FeedWindow.tsx) · [FeedGeometry и состояние сеанса](../../apps/web/src/lib/feedWindow.ts) · [FeedPage](../../apps/web/src/pages/FeedPage.tsx) · [Стенд](../../tools/site-checks/feed-perf.mjs).

## Воспроизведение

```powershell
# Исходная и диагностическая реализация. Архив повторов описан в BASELINE.md.
$env:BUBBLE_PERF_WINDOW = $null
node tools/site-checks/feed-perf.mjs depth 2 desktop 240
node tools/site-checks/feed-perf.mjs mount 2 desktop 240

# Оконный вариант.
$env:BUBBLE_PERF_WINDOW = '1'
node tools/site-checks/feed-perf.mjs depth 2 desktop,mobile 240
node tools/site-checks/feed-perf.mjs depth 1 desktop 1000
node tools/site-checks/feed-perf.mjs media 2 mobile 20
node tools/site-checks/feed-perf-report.mjs <каталог-прогона>
```

Для полного и оконного вариантов сохраняются одинаковые события trace. До окна измерения позиция ставится на ту же опорную запись. При подготовке оконного варианта стенд прокручивает проставки до появления нужной записи, поэтому число уже инициированных загрузок вне измеряемых окон может отличаться. Сетевая колонка относится к фактическим обращениям к HTTP-серверу фикстур во время измерения. Прокси S3, `no-store` и реальное повторное декодирование проверяются отдельно.

## Сравнение трёх реализаций на desktop

Chrome 158, 1280 × 850, CPU 1×. Для исходной ленты приведена медиана трёх повторов. Для прототипа и окна приведены значения двух повторов через косую черту. ## Мобильный профиль и медиа

## Найденные регрессии

- Открытое поле оставалось смонтированным, но после быстрого прыжка вниз последний пост мог оказаться за границей viewport, когда оценки заменялись реальными высотами. Сохранена привязка к нижней границе при обновлении окна.
- Промежуточная версия могла восстановить старую опору поверх явного возврата наверх при обновлении данных. Явный сброс прокрутки снимает ожидающую опору.
- Контейнер карточки изменил действие существующих CSS-селекторов прямых потомков. Селекторы базовой и мобильной раскладок расширены на строки окна.
- Событие `selectionchange` вызывало обновление окна при обычном движении каретки. Планирование теперь реагирует на появление или исчезновение выделения в ленте.
- Playwright Firefox по умолчанию завершался до загрузки страницы. Изолированный запуск на loopback с `MOZ_DISABLE_CONTENT_SANDBOX=1` позволил выполнить те же функциональные сценарии в Firefox 159. Флаг относится только к среде локальных проверок.

## Границы результата

Тяжёлые начальные эффекты мобильной оболочки, сроки скачивания фото и аватаров относятся к 4B. Эмуляция 4× измеряет CPU на настольном устройстве и не заменяет Honor 9 Lite. Windows-тест с touch подтверждает DOM-фокус, выборку кадров и прокрутку, а экранная клавиатура и реальный GPU телефона требуют отдельного устройства. Видео стороннего сервиса требует отдельной проверки воспроизведения. Возможность глобального аудиоплеера проверяется локальным WAV. Оконная версия использует браузерный HTTP-кеш по тому же URL. Объём Query сохранил существующие правила жизни и растёт с полученными страницами текущей ленты. После ухода действует срок очистки Query; окно не создаёт копию DTO.

Для этапа 4B рекомендуется **GPT-6.2 Astra, высокое усилие**. Начать с оставшихся пауз на первых 20 постах и готовых слайдов. Сохранить окно как исходную реализацию для новых сравнений. Разобрать, что происходит между жестом, сменой геометрии оболочки и кадром с новым содержимым. Для холодных фото и поздних аватаров отдельно проверить конкуренцию запросов при одинаковом кеше.
