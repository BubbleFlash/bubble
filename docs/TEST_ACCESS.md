# Доступ к тестовому стенду

Тестовый workflow добавляет шлюз для веб-сайта, `/api/`, `/uploads/` и `/socket.io/`. Администратор управляет режимом и общими учётными данными через «Панель модерации → Тестовый доступ». После входа через шлюз пользователь входит в свой аккаунт Bubble. Общий пароль хранится как хеш.

## Код и конфигурация

- `tools/test-gate/server.mjs` обслуживает вход, проверку и сессионную cookie. На стороне API правила и состояние хранят `testGateController.ts` и `TestGateSettings.ts`. Изменение настроек или включение режима отзывает ранее выданные сессии. Срок сессии 12 часов.
- `docker-compose.test-gate.yml` требует `TEST_GATE_SECRET` для запуска шлюза и связи с API. Владелец задаёт его в серверном env-файле. Развёртывание использует базовый Compose и тестовое дополнение по [DEPLOYMENT.md](DEPLOYMENT.md).
- Публичный вход идёт через HTTPS-прокси; внутренние API, realtime, шлюз и MongoDB держатся в приватной сети. Прямые подписанные ссылки используют собственную политику хранилища.

## Приёмка человеком

На разрешённом стенде проверь запросы без сессии к главной, API, загрузкам и `/socket.io/`. Затем проверь неверный и верный общий вход, обычный вход Bubble и отзыв старой сессии после согласованной смены настройки. Подтверди снаружи, что API и realtime недоступны напрямую. Автоматические проверки шлюза перечислены в [TESTING.md](TESTING.md).
