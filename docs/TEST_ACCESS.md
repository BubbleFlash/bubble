# Доступ к тестовому стенду

Тестовый workflow запускает дополнительный шлюз перед веб-сайтом, `/api/`, `/uploads/` и `/socket.io/`. Режим, общий логин и пароль администратор задаёт в панели модерации во вкладке «Тестовый доступ»; модераторам она недоступна. После общего входа пользователи входят в свои аккаунты Bubble. Пароль сохраняется в базе только в виде хеша.

До первого развёртывания этой версии владелец стенда должен добавить в существующий `/opt/bubble/.env.production` значение `TEST_GATE_SECRET`. Секрет подписи и связи шлюза с API должен содержать не менее 32 символов; его можно сгенерировать командой `openssl rand -hex 32`. Ограничьте доступ к файлу. Сборка и запуск без секрета завершатся ошибкой.

После развёртывания режим по умолчанию выключен. Войдите как администратор Bubble, откройте панель модерации → «Тестовый доступ», задайте логин и пароль и включите режим. При включении или смене данных действующие сессии тестового доступа отзываются; пароль понадобится ввести заново. Срок сессии — 12 часов. Если логин и пароль потеряны, восстановление требует доступа администратора к базе сервера.

Развёртывание использует `docker-compose.prod.yml` вместе с `docker-compose.test-gate.yml`. Последний предназначен только для тестового стенда. Публичный доступ должен идти по HTTPS через веб-прокси; API, realtime, шлюз и MongoDB не должны иметь отдельных публичных портов. Прямые ссылки на внешнее объектное хранилище действуют по собственным правилам хранилища и не проходят через этот шлюз.

После развёртывания проверьте без сессии главную страницу, прямые адреса API, загрузок и `/socket.io/`, затем неправильный пароль, правильный пароль и обычный вход Bubble. Проверьте снаружи сервера, что API и realtime недоступны напрямую. Доставку и изменение серверного файла выполняет владелец.
