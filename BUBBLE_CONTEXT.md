## 1. Архитектура и точки входа

Bubble основан на Commune, откуда унаследованы имена npm-пакетов `@commune/*`. Сохраняй MIT-лицензию и авторство. Монорепозиторий использует npm workspaces и Node.js ≥20. Клиентские пути ниже относительны к `apps/web/src/`, серверные — к `apps/api/src/`.

| Граница | Владелец и путь данных |
| --- | --- |
| Web | React 18, Router, TanStack Query 5, Vite 6. `main.tsx` монтирует Query → Router → Auth → Music → Realtime. `App.tsx` выбирает оболочку и маршрут. |
| HTTP | Браузер → Nginx `/api/` → Express. `server.ts` запускает API, `app.ts` задаёт порядок middleware, `routes/index.ts` связывает валидацию и права с контроллером. |
| Данные | API → Mongoose 8 → MongoDB 7 в Compose. `models/` задаёт схемы и индексы, `utils/serializers.ts` формирует DTO. `storageService.ts` и `s3Client.ts` работают с S3. |
| Медиа | Nginx `/uploads/` → API. Для отдельных операций браузер обращается в S3 по временной подписи. [Доставка медиа](#изображения-и-прочие-файлы). |
| События | API после записи → отдельный Socket.IO 4 → вкладка через `/socket.io/`. Realtime проверяет сеанс и членство через внутренний API, без прямого доступа к MongoDB. |
| Общий контракт | `packages/shared/src/index.ts` — Zod и DTO, `rateLimits.ts` — политики лимитов, `telemetry.ts` — форматы диагностики. |

В сборке web API и сокет используют origin сайта, в dev возможны отдельные порты. [Локальный запуск](docs/DEVELOPMENT.md) · [Схема развёртывания](docs/DEPLOYMENT.md).

## 2. Обязательные правила разработки

При оптимизации, рефакторинге и исправлении технических ошибок сохраняй согласованное поведение продукта. Изменения функциональных требований, прав доступа, пользовательских сценариев и бизнес-правил согласуй заранее. Если трактовка неоднозначного требования существенно меняет поведение системы, передай варианты и их последствия владельцу проекта и дождись решения.

1. Проследи действие от штатного экрана через hook, HTTP/событие, право и модель до итогового DTO. Для общего изменения ищи импорты, URL, query key, события, CSS-класс и фикстуры. У `PostCard` проверь ленту, профиль, группу, поиск и отдельную запись.
2. Бизнес-правило выполняет серверный владелец, UI показывает подсказку и результат. Переиспользуй предметный сервис. Новый слой, очередь, зависимость или глобальное состояние требуют конкретного потребителя и выигрыша с учётом стоимости сборки и сопровождения.
3. Проверь чтение старого DTO и документа без нового поля. Проследи запись, индексы, агрегации, пагинацию, кэш и обратные связи. Укажи default и последствия возможной миграции для владельца.
4. Определи исход при повторе, тайм-ауте, отмене, конкурентной записи и смене аккаунта. Изменяемое ограничение проверяй в самой записи БД. До повтора неидемпотентной операции с неизвестным результатом сверь состояние. Для оптимистической мутации отмени старое чтение и защити более свежий результат от отката.

### React, запросы и освобождение ресурсов

- На клиенте серверные DTO хранит TanStack Query, состояние формы — ближайший компонент, параметры навигации — маршрут. Производные значения вычисляй из источника, частое состояние изолируй у подписчика. Стабильный ID и идентичность неизменённых элементов сохраняют строки списка.
- В `main.tsx` свежесть 30 с, хранение неактивного кэша 15 мин, refetch при focus выключен. Один retry, кроме API 4xx и восстановления с паузой. Уточняй исключения hook. Ключ включает фильтр и область доступа. Перед новым GET проверь существующее чтение, инвалидацию, событие и резервный опрос. Передавай AbortSignal до транспорта. После мутации согласуй детали, счётчики, `pages` и `pageParams`.
- Подписывайся из эффекта, отправляй действие из обработчика. При смене владельца сними тот же callback, закрой канал, отмени fetch, таймеры и rAF, отключи observers, освободи object URL и аудио. Поздний результат сверь с аккаунтом, сущностью или поколением. Учитывай повторный mount в dev StrictMode.
- Перед мемоизацией измерь React commits и их длительность на действие. Виртуализацию проверяй со скроллом, фокусом и восстановлением позиции. Для утечки сравни активные ресурсы и память после одинакового числа циклов «открыть → закрыть» и паузы.

## 3. Сеанс, вкладки и потеря соединения

`store/auth.tsx`, `lib/api.ts`, `lib/browserSession.ts` ↔ `authController.ts`, `authService.ts`, `User`, `RefreshToken`, `AuthToken`. Access JWT хранится в памяти, хеш ротируемого refresh-токена с TTL — на сервере. HttpOnly cookie `commune_rt` ограничена `/api/auth`. При импорте транспорта начинается refresh. Снимок профиля служит для ранней отрисовки.

Регистрация возвращает `verificationRequired: true` для email, сеанс выдаётся при подтверждении. Проверь `/register` и вкладку встроенной формы. `AccountSettings.tsx`, `accountService.ts`, `accountDeletion.ts` владеют сменой адреса, пароля и удалением. До подтверждения действует прежний адрес. Проверь назначение и одноразовость токена, срок, актуальность/отзыв сеанса, восстановление до истечения периода удаления и повтор порционной анонимизации после него. [Тест аккаунта](apps/api/src/tests/accountLifecycle.integration.test.ts).

`lib/tabQueries.ts` обменивает только первые страницы `feed/following`, `feed/all` и счётчики `unread-count`, `unread-messages`. Снимок ограничен подтверждённым аккаунтом, поколением и временем последней инвалидации. Соседи помечают ленту через `refetchType: "none"`. Без свежего снимка или BroadcastChannel вкладка читает REST. [Сбои сеанса](#сеанс-и-регистрация).

## 4. API, MongoDB и безопасность

### Безопасность и права доступа

- `requireAuth` проверяет Bearer JWT, актуальное состояние аккаунта и версию сеанса. `requireActive` проверяет подтверждение почты при `REQUIRE_VERIFIED_EMAIL`, `requirePublishing` — ограничения публикации. Порядок middleware сверяй по маршруту. Роли сайта, полномочия группы и участие в диалоге независимы.
- Сверяй право получателя при чтении, записи, поиске, экспорте и выдаче вложенного превью. Для постов используй `postAccess.ts` и сериализаторы. Контроль доступа к ЛС опирается на членство, сквозного шифрования в протоколе нет. [Границы файлов](#изображения-и-прочие-файлы).
- Учитывай HTTPS, `CLIENT_ORIGIN`, `COOKIE_SECURE`, CORS, `originGuard` и `TRUST_PROXY`. В `app.ts` платёжный webhook получает сырое тело до JSON-парсера. Проверяй подпись, повторы и порядок событий. [Серверные права Plus](docs/PLUS.md).
- Для диагностики фиксируй UTC, шаблон маршрута, статус, Request ID, имя лимитера и `Retry-After`. Сопоставляй HTML, refresh и предметный API с журналами за один интервал. [Наблюдаемость](docs/MONITORING.md).

### Выборки и запись в MongoDB

- Ограничивай страницу и проекцию. Сортировка и курсор используют одни поля с уникальным последним ключом. Фильтруй видимость до лимита. Проверь совпадающие даты, исчезнувшую связь, пустую и последнюю страницы.
- В `postController.presentPosts` данные для нескольких записей выбираются пачкой. Собери уникальные ID, используй `$in`, агрегацию или ограниченный populate. `lean()` подходит чтению без методов документа. `Promise.all(rows.map(findById))` сохраняет N+1. [Пример в CMS](#открытые).
- Для горячего запроса сними число операций на страницу и `explain("executionStats")` на представительной изолированной базе. Сравни `nReturned`, `totalDocsExamined`, `totalKeysExamined` и стадию сортировки. Для записи проверь атомарность, частичный отказ, реальный индекс и его стоимость при обновлении.

### Лимиты и диагностика

`middleware/rateLimit.ts` держит HTTP-счётчики в памяти процесса, `rateLimitSettings.ts` хранит политику в MongoDB, `quotaCounter.ts` резервирует квоты действий атомарно в БД. Редакция правила управляет заменой MemoryStore и закрытием старых таймеров. Квоты действий, общий HTTP-переключатель, капча, пауза регистрации, ограничения realtime и прокси имеют разные области. Правки правил должны сохранять чужие бюджеты и доступ администратора к настройкам. [Инциденты квот и сети](#лимиты-и-доступность).

## 6. Socket.IO и восстановление состояния

`services/realtime.ts` (API) → внутренний HTTP → `apps/realtime/src/server.ts` → `lib/realtime.ts` → `store/realtime.tsx` → Query. Доставка best-effort с тайм-аутом и паузой после сбоя. Push — отдельный канал.

- На handshake клиент передаёт свежий JWT в `auth`. `membership.ts` проверяет сеанс через API, отдельно кэширует участников и отсутствие диалога. Сохраняй проверки Origin, секрета внутренних маршрутов, события, payload и членства.
- `message:new`, `message:read`, `message:changed` и `notification:new` обновляют клиентские представления. `conversation:join`/`conversation:leave` управляют комнатой диалога, `typing` и `presence` передают временное состояние, `visibility` влияет на подавление push.
- Один клиент Socket.IO на авторизованную вкладку с включённым realtime. Обмен снимками Query не объединяет сокеты. Комнаты, подключения, presence, лимиты и кэш членства локальны для процесса. При масштабировании потребуется согласовать межпроцессную доставку и маршрутизацию polling. [Контракт](docs/REALTIME.md) · [Регрессии](#жизненный-цикл-и-регрессии).

## 7. Медиа и PWA

### Изображения и прочие файлы

`lib/images.ts` готовит фото, `useImageDraft` и `lib/upload.ts` управляют подготовкой и передачей. БД хранит путь изображения. `GET /uploads/:file` проверяет модерацию до редиректа или обработки ETag. Видимость записи для конкретного зрителя маршрут не проверяет. Ссылка из другого допустимого материала может сохранить файл доступным.

| Объект | Передача и выдача |
| --- | --- |
| Обычное фото | `POST /api/uploads` через API. При чтении прокси выдаёт `private, no-cache`. При включённой прямой доставке `AssetImage` запрашивает `?direct=1`, подпись S3 действует 60 с. При сбое прямой загрузки — одна попытка через прокси. |
| Фото ЛС | `/messages/images` и `/messages/images/:imageId` — отдельная авторизованная загрузка и выдача. Подпись на чтение действует 120 с. |
| Музыка | `MusicPage` → `POST /music/uploads/sign` → `PUT` в S3 → `POST /music/uploads/complete`. `musicUploadService` проверяет владельца, сохранённый объект и повтор завершения. Ссылка на проигрывание/скачивание действует 600 с. |

Уже выданная ссылка действует до истечения срока. Перед удалением объекта проверь обратные ссылки постов, комментариев, профилей, групп и обоев. [Контракт загрузок](docs/UPLOADS.md) · [Инциденты доставки](#изображения-и-загрузка).

`MusicPlayerProvider` в `store/music.tsx` владеет аудио поверх маршрутов, `musicSession.ts` — снимком вкладки, `MusicAttachments`, `MusicTrackList` и `ProfileMusic` — представлениями каталога и очереди. Выдача библиотеки профиля имеет `private, no-store`. Скрытие библиотеки оставляет трек в каталоге. При изменении отношений или видимости обновляй `profile-music`, включая восстановление соединения. [Регрессии плеера](#музыка).

### Вкладки после сборки и service worker

`public/sw.js` пропускает `/api`, `/uploads` и `/socket.io`. Навигация сначала обращается к сети, с возвратом к сохранённой оболочке или offline-странице. Для хешированных `/assets/` применяется cache-first. HTML-ответ на запрос ресурса нельзя сохранять под именем JS. Версии оболочки, SW и заголовки Nginx должны позволять обновиться ранее открытой вкладке. [Сбои старой сборки](#оболочка-и-pwa).

## 8. Aero, прокрутка и браузеры

### Дизайн и общие компоненты

- Windows 7 / Frutiger Aero, у плеера — композиция Windows Media Player 12. В `main.tsx` после базы, темы и скелетонов подключаются `aero-tokens.css`, `aero-themes.css`, затем `aero-components.css`, `aero-shell.css` и `aero-home.css`. Используй `--aero-glass-blur`, `--aero-glass-saturation` и размеры нижнего дока из токенов.
- Общие примитивы — `AeroTitlebar`, `BrandMark`, `Icon`, `NavigationIcon`, `Avatar`, `AssetImage`, `Skeleton`, `PostCard` и `ImageGallery`. `lib/navigation.ts` связывает `Header`, `LeftNav` и `BottomNav`. В диалогах проверь `useDialogBackdrop`, Escape, возврат фокуса и доступ к плееру. [Уроки компонентов](#общие-компоненты-и-ввод).
- `lib/appearance.ts`, `lib/siteFont.ts`, `SettingsPage` и `appearance.css` владеют фоном, шрифтом, акцентом и прозрачностью. Проверь предпросмотр, возврат из чужого профиля, reload и default старых настроек. [Дизайн](docs/DESIGN.md).

### Браузерная совместимость и слабые устройства

- Цель JS-сборки — ES2020 (`apps/web/vite.config.ts`). Минимальные версии всех браузеров не установлены. Проверяй наличие нужного API, secure context, отказ разрешения и деградацию. Web Locks, BroadcastChannel, storage, autoplay, `AbortSignal.any/timeout` и popover имеют разные условия поддержки.
- До 1100 px включительно действует мобильная оболочка. Обычно прокручивается документ. На Firefox Android у вошедшего пользователя вне публичного лендинга прокручивается окно Bubble, у ЛС возможна своя область. Используй `lib/scrollToTop.ts` и `lib/feedNavigation.ts`. [Исправления Firefox](#прокрутка-и-исправления-firefox).
- Проверь ширины по сторонам breakpoint, длинную строку, клавиатуру, масштабирование, поворот, док и `prefers-reduced-motion`. Для больших blur, теней, масок, sticky и анимации при скролле сравни paint/compositing на длинной ленте. На слабом устройстве измерь время до действия, плавность жеста, память и трафик.
- Выбирай по риску Chrome/Edge, Firefox, WebKit, установленный Opera GX, Safari macOS/iOS. Симулятор iOS дополняет проверку раскладки. Скорость, жесты, клавиатуру, адресную строку, фон, аудио и push проверяй на целевом аппарате. Для локального Android с отдельными dev-портами обеспечь доступ к web, API и при необходимости realtime.

## 9. Производительность и измерения

До правки определи действие, метрику и допуск. Для базы и кандидата зафиксируй ревизию и локальные отличия, сборку, машину/телефон, ОС, браузер, viewport, данные, сеть, кэш и фоновые нагрузки. Повтори холодный и прогретый сценарии раздельно, укажи разброс. При смене методики повтори обе серии. Источник базы — предоставленный checkout или сопоставимый артефакт. Общих численных бюджетов для всех экранов нет.

Отклонение в пределах естественного разброса само по себе не доказывает регрессию. Если сопоставимые замеры подтверждают существенное ухудшение относительно базы, задача не завершена. Установи причину и попытайся устранить её в пределах задачи, затем повтори замеры. Если устранение невозможно или выходит за согласованные границы, представь владельцу результаты и согласуй дальнейшие действия. Ухудшение одной подсистемы ради ускорения другой требует обоснования замерами обеих и предварительного согласования.

| Изменение | Что сравнивать в одинаковых условиях |
| --- | --- |
| Старт и действия | До видимого контента, LCP/CLS, задержка действия, размер JS и медиа, HTTP по endpoint. INP относится к взаимодействиям визита. Указывай отдельно полевые данные и лабораторную задержку. |
| React, CSS, память | Число и длительность commits на действие, длинные задачи, интервалы rAF, layout/paint/compositing, активные ресурсы после повторных переходов. Для визуального дефекта проверь сам жест. |
| API и MongoDB | Счёт запросов при увеличении страницы, p50/p95/p99, CPU, RSS, план выборки и индексы. Указывай состав трафика, число пользователей и длительность. |
| Сеанс, сеть, медиа | GET, переданные байты, статусы и повторы, handshake на вкладку, активные подписки после закрытия, запросы до видимости и после открытия вложения. Проверяй выход, повторное открытие и медленную сеть. |

Для маршрутов используй lazy import и `lib/prefetch.ts` (пропускает prefetch при saveData/2G), для карточек — `useNearViewport` и пакетную проверку треков. При профилировании старта учитывай передачу ранних ответов `index.html` в `lib/api.ts` и iframe сторонних скриптов. YouTube в `LinkContent` использует lazy iframe. Для новостей `s-maxage` влияет только при наличии соответствующего внешнего кэша, гостевые `/public/posts` и `/public/posts/:id` отдаются с `no-store`.

`tools/measure-feed.mjs` моделирует 60 карточек с подменёнными API и Audio, считает React commits при 20 тиках и интервалы rAF. `PERF_VERIFY=1` добавляет проверки изоляции часов, черновика и медиа. `check:site` даёт browser timings. `check:tabs` использует реальные локальные API, Socket.IO и MongoDB для 1/2/5 вкладок. `check:load` моделирует пользователей с существующими сеансами за одним IP. Параметры, границы каждого режима и выходные отчёты — в [PERFORMANCE.md](docs/PERFORMANCE.md).

## Известные ошибки и неудачные решения

Записи сгруппированы по подсистемам. В каждой указано, что наблюдалось, какое решение действует в коде и чем проверить его при следующем изменении. Ссылки на тесты обозначают способ проверки. Результат прогона относится только к зафиксированному в нём окружению. Имена API-тестов относятся к `apps/api/src/tests/`, `candidate.spec.ts` — к `tools/site-checks/`.

### Сеанс и регистрация

- **Ложный выход при восстановлении.** Вкладки могли отправлять refresh с уже заменённой общей cookie. Серверный отказ устаревшей ротации не должен очищать cookie победившего запроса. Теперь `lib/api.ts` объединяет refresh одного поколения внутри вкладки, `withSessionCookie` сериализует изменения cookie через Web Locks. Без Locks предусмотрен ограниченный повтор при 401 и подсказке о сеансе. Поздний ответ нельзя применять после выхода или смены аккаунта. Проверяй истечение JWT в `check:tabs` с `BUBBLE_TAB_CHECK_EXPIRE=1` и путь без Locks отдельно.
- **Временный отказ принимался за гостя.** Гостевая фикстура с пустым 401, в свою очередь, зависала в ожидании определённого исхода. При refresh проверяй и статус, и тело. `401` с `No session` или `Session expired`, структурированное ограничение, сеть/5xx и 429 идут разными путями. Cooldown по `Retry-After` общий для вкладок поколения. `candidate.spec.ts` проверяет временный отказ, терминальный ответ и паузу второй вкладки. При повторном подтверждении уже известного гостя сохраняй публичный кэш, при смене аккаунта очищай приватный.
- **Новая почта получала занятый публичный ID.** Составной поиск в регистрации пропускал совпадение username. Требование построить глобальный уникальный индекс перед каждой регистрацией блокировало свободные ID на базе со старыми дублями. `authService.ts` отдельно проверяет email и имя с общей collation для username. `User.ts` сохраняет объявление глобального индекса и создаёт частичный `unique_registered_username` для новых email/Google-аккаунтов с `registrationUsernameProtected: true`. Обрабатывай конфликт БД после предварительного чтения. Проверь регистр, конкурентную вставку и отдельный свободный ID среди старых дублей. Меры модерации адресуй по внутреннему ID: неоднозначность старой профильной ссылки этим не устраняется. `78d008c`, `registration.test.ts`, `google.test.ts`.
- **Пауза регистрации и одноразовая капча.** Проверка только в email-форме не покрывает создание через Google. Применяй паузу в обеих точках создания, сохраняя вход существующего пользователя. `registrationCaptcha.ts` связывает задание с cookie, редакцией политики и сроком, подходящая попытка расходует его также при неверном ответе. В прошлом перенаправление после регистрации скрывало сообщение во встроенной форме. Теперь экран показывает «Проверьте почту», а пользователь с неподтверждённым адресом и верным паролем может повторно получить письмо. Гостевая форма получает состояние паузы через маршрут капчи, даже если сама капча выключена. Проверь новое задание с сохранённым вводом, новый и существующий Google-аккаунт, ранее отправленное письмо и подтверждение. `b854ac4`, `78d008c`, `antispam.integration.test.ts`, `candidate.spec.ts`.

### Лимиты и доступность

- **Несколько аккаунтов за одним IP получали 429 (#64, #76, #111).** IP-бюджет объединял независимых пользователей за NAT. Для общих авторизованных запросов учитывается подписанный principal, у гостя остаётся IP-бюджет. У refresh отдельны поиск по cookie и лимиты аккаунта/IP. Сохраняй `X-RateLimit-Limiter`, `Retry-After`, возможность администрировать правило и введённый черновик. Проверяй общий IP, смену IP одного пользователя, холодное окно правила и повтор без смены редакции. В `rateLimit.test.ts` есть варианты на 20/50 аккаунтов, также см. `candidate.spec.ts` и `check:load`.
- **Квоты действий и начало новой переписки (#76).** У прежней IP-защиты не было отдельных квот на публикации, а отправители за общим NAT разделяли лимит сообщений. Первая и дальнейшие отправки используют общую квоту сообщений, новый диалог дополнительно резервирует цель пары в `quotaCounter.ts`. Проверяй два одновременных начала диалога с одним адресатом, разные пары и исчерпание одной квоты при доступной другой. Аналогично пост и репост делят квоту публикаций, комментарий и ответ — квоту комментариев. Счётчик фиксированного окна может быть израсходован до сохранения материала. На стыке окон возможен всплеск. TTL удаляет старые счётчики, границу ожидания задаёт само окно. `antispam.integration.test.ts`, `messageController.ts`.
- **HTML доступен, восстановление сеанса или лента недоступны (#160).** Сопоставь один маршрут сети и одну версию клиента с отдельными результатами HTML, refresh и публичного GET, именем лимитера и журналами. По одному `CF-Ray` установить виновный слой нельзя. `reachability.spec.ts` покрывает отдельные обращения. Потребительские сети остаются [открытой проверкой](#открытые).

### Лента, связи и уведомления

- **Обновление ленты вызывало GET всех прочитанных страниц (#130).** Одна инвалидация infinite query перечитывала всю цепочку. `refreshFeed` в `lib/feedNavigation.ts` отменяет предыдущее чтение, согласованно обрезает `pages` и `pageParams` и обновляет активную ленту. Соседним вкладкам передаётся отметка об устаревании снимка. Посчитай GET после двойного клика, перехода из профиля и последующей догрузки. `candidate.spec.ts`, `check:tabs`.
- **Закрепление, скрытие и редактирование меняли состав страницы (#117, #120, #122).** Закрепление занимает место на первой странице и исключается из последующих. При `limit=1` первая страница может состоять только из закрепления. Фильтры скрытого автора личной записи и скрытой группы применяются к текущей записи до ограничения выдачи. Чужой репост проверяется отдельно. Пять минут для правки личной записи и `updatedAt` проверяются при записи. Проверь недоступное закрепление, смену закрепления между чтениями и сохранение из двух форм у границы срока. `postController.ts`, `reposts.integration.test.ts`.
- **Смешивались автор, группа, оригинал и репост (#29, #82, #105).** Following использует подписку на автора для личных записей и членство для групповых. Личный профиль исключает записи группы. Лайк репоста добавляет лайк доступному оригиналу, снятие относится к выбранной записи. Скрытого автора проверяй в DTO ленты, репоста, поиска и экспорта. 18+ управляет показом фото. Старые платные записи исключены, права Plus отделены. Проверь обе последовательности лайков и два разных права доступа к одной цитате, включая ЛС. `postAccess.ts`, `repostService.ts`, `reposts.integration.test.ts`.
- **Ответ терял адресата при редактировании обращения (#9).** Храни ID родительского комментария отдельно от текста «Имя,». Проверь удаление префикса, смену адресата и удалённый родитель. Лайки и ответы должны обновлять список и счётчик на карточке. `CommentInput`, `InlineComments`, `postController.ts`, `reposts.integration.test.ts`.
- **Онлайн ломал пагинацию друзей (#118).** Пересортировка всех строк по меняющемуся онлайну давала пропуски между страницами. Дедупликация UI скрывала лишь повторы. `relationshipController.ts` использует устойчивый курсор с датой и ID. Отдельный preview вправе отсортировать по онлайну весь подходящий набор перед обрезкой. В поиске людей `searchController.ts` фиксирует снимок онлайна. Проверь смену статуса между страницами и стоимость preview на большом числе друзей. `relationships.integration.test.ts`, `search.test.ts`.
- **Индикатор онлайна жил отдельно от аватара (#85, #118, #128).** В `Avatar` статус привязан к обёртке. Полученный `online: false` — известное значение. Дополнительное чтение требуется для чужого аватара при отсутствии статуса, включённом `trackOnline` и подтверждённом сеансе. `useProfilePresence` собирает до 50 имён в `/profile-presence`, API отдельно группирует ID для realtime. Не подключай аватары групп к проверке пользователей. Проверь реальный realtime-процесс, второй аккаунт, фон, закрытие последней вкладки и число запросов на список.
- **Неверное прочтение повторного уведомления и устаревшие счётчики (#84).** Лайк или follow может переиспользовать ID с новым `createdAt`. `notificationController.ts` отмечает конкретные версии по паре ID/время, «прочитать все» ограничивает серверным временем. Без параметров пагинации возвращается массив, с ними — страница. Курсор вычисляй и при исчезнувшем авторе. Проверь одно новое событие во время чтения старого, скрытие категории и возврат истории, независимые ссылки на актёра и событие, счётчик во второй вкладке. `useSocial.ts`, `social.test.ts`, `candidate.spec.ts`, `check:tabs`.

- **Публичная главная и дневник устаревали независимо (#66, #77, #107).** Безусловный ранний GET после изменения главной тратил сеть. `index.html` выбирает предзагрузку по маршруту и подсказке о госте. `DevelopmentWidget` в общей оболочке живёт между переходами и перечитывает данные при изменении `location.key`. Проверяй первый запрос перед React, переход внутри SPA, ссылку гостя и очистку кэша при смене аккаунта. Состав команды сайта хранится по ID аккаунтов с актуальными именами и ролями. `siteContentController.ts`, `reachability.spec.ts`.

### Модерация и права групп

- **Жалобы на разные комментарии одного поста конфликтовали.** В старых строках `CommentReport.post` мог означать родительский пост или сам комментарий. `CommentReport.ts` сохраняет селекторы обоих форматов, `snapshot.parent` и частичный уникальный `reporter_comment_present` по `reporter, comment`. Проверяй две разные жалобы, повтор на тот же комментарий, очистку родителя и фактические индексы отдельной MongoDB. `reportController.ts`, `moderation.integration.test.ts`, `reposts.integration.test.ts`.
- **Скрытый материал, удалённое содержимое и жалоба расходились (#88, #89, #112).** Скрытие обратимо и сохраняет служебное превью по роли. Безвозвратная очистка оставляет аудит, `purgedAt` фиксирует очистку, `deletionPending` — незавершённую обработку связей/медиа. Старый `removed` не доказывает удаления байтов. Изменение материала должно закрыть связанные жалобы. Проверь отказ в публичной выдаче, сохранение общего файла, повтор после частичного сбоя, фильтры и уже открытое меню второго модератора. `moderationService.ts`, `moderationController.ts`, `moderation.integration.test.ts`.
- **Старый пост, скрытый сегодня, оказывался внизу CMS (#112).** Сортировка по ID отражала создание материала. `listContent` объединяет посты, комментарии и обои по времени события модерации с fallback на `purgedAt`/`createdAt`, затем по ID и типу. Сортировка каждой ветви, слияние и сравнение с курсором должны совпадать. Проверь две страницы с одинаковым временем и старыми записями без времени события. [Контроллер](apps/api/src/controllers/moderationController.ts).
- **Права управляющего после выхода/вступления.** Исторические формы членства и повторное вступление делают проверки только по ID пользователя недостаточными. Сопоставляй владельца по `Community.creator`, действующее назначение — по ID членства. Проверь старую строку владельца, выход во время передачи владения, повторное вступление бывшего управляющего и изменение роли параллельным запросом. `communityAccess.ts`, `communityController.ts`, `reposts.integration.test.ts`.
- **Старый экран администрирования вместо CMS.** В истории не удалось разделить влияние маршрута, версии ветки и роли. Сверяй `/moderation`, `/admin` и `/admin/errors` в `App.tsx`, доступ в обеих навигациях и решение API в текущем сеансе. Одна видимая ссылка или выдача роли не доказывает исправления причины.

### Жизненный цикл и регрессии

- **Событие ЛС пришло до GET, дважды или во время refetch (#7).** В `store/realtime.tsx` и `useMessages.ts` данные должны сходиться по ID в истории, списке диалогов и счётчиках. После reconnect восстанавливай нужные комнаты и делай REST-сверку пропущенного. Для ЛС с репостом передавай событие с признаком, превью выдавай каждому получателю по его правам. Уведомление автору оригинала ведёт к оригиналу. Проверь две сессии, изменение/удаление, поздний GET и разрыв. `reposts.integration.test.ts`, `check:tabs`.
- **Умножение обработчиков, фоновых GET и ложный офлайн.** `startRealtime` повторно использует клиент вкладки, `joinConversation` возвращает очистку комнаты. Пара «вход/выход» должна снимать тот же callback, завершать временные индикаторы и не оставлять подписок прошлого сеанса. Различай фон, последнюю закрытую вкладку собеседника и видимость для push. Считай handshakes, подписки и GET при смене диалогов и JWT. Проверь WebSocket, Socket.IO polling и отдельную REST-сверку. `apps/realtime/src/tests/server.test.ts`, `membership.test.ts` в том же каталоге, `check:tabs`.

### Музыка

- **Лента перерисовывалась на тиках плеера.** Частое `currentTime` в общем контексте будило потребителей очереди и команд. `MusicTimeContext` из `store/music.tsx` изолирует часы. При правке плеера сравни commits ленты при одинаковой серии `timeupdate` в `measure-feed.mjs`, проверь сохранность черновика и реальное проигрывание отдельно.
- **Очередь исчезала на reload, вкладки играли одновременно (#137, #138).** `musicSession.ts` хранит в sessionStorage аккаунт, трек, очередь и исходный порядок, источник, position, repeat/shuffle и намерение продолжить. После подтверждения аккаунта запрашивается новая ссылка, `pendingSeek` ждёт метаданных. На `pagehide` сохраняется позиция без сериализации очереди на каждом тике. BroadcastChannel и storage согласуют трек, очередь и владение звуком между вкладками. Проверь перехват звука, exit, повреждённый storage, отказ autoplay с ручным Play, выключение shuffle после reload. Для перемотки WAV-фикстуре нужен HTTP Range (206), а тесту — реальное ненулевое время. `candidate.spec.ts`.
- **Короткая или чужая очередь при выборе того же трека (#103, #163).** Каталог, профиль и вложения используют ID трека вместе с `queueSource`. `ProfileMusic` догружает страницы по курсору, `MusicTrackList` учитывает устаревший результат смены источника. Страница музыки использует `/music/picker` с `{ tracks, nextCursor }`, старый `/music` имеет других потребителей. Проверь следующий трек после последнего в preview, быстрый выбор другой очереди и отказ второй страницы. Ошибочная фикстура `/music` давала нулевой счётчик запросов picker. `musicPagination.integration.test.ts`.
- **Автозаполнение музыкальной формы.** Чтение тегов и длительности — независимые операции в `MusicPage`. Имя файла даёт подсказку, непустой тег уточняет её, ручное значение и более новый файл имеют приоритет. Пять минут на переименование проверяет сервер для загрузившего. Проверь быструю смену файла, правку вручную и отказ чтения тегов.
- **Плеер прыгал при сворачивании, диалог выбора сдвигался при появлении плеера (#139).** Раздельно сохранённые координаты двух режимов возвращали окно на старое место. `prepareModeSwitch` переносит координаты перед сворачиванием. Диалог редактирования использует структуру загрузки также вне `.music-page`. Проверь полный → компактный → полный после перетаскивания, открытый выбор вложения и свайпы мини-плеер → плеер → очередь. При repeat кнопка «назад» переходит по кругу в начале первого трека, после трёх секунд начинает текущий заново.

### Изображения и загрузка

- **Успешное сохранение показывало ошибку (#59).** Безусловный разбор JSON падал на пустом успешном теле. `lib/api.ts` читает текст и разбирает непустое тело. Проверь 204, обычный JSON, ошибку и фактический результат после возврата на экран. Для фото используй `lib/upload.ts` с прогрессом передачи.
- **Лимит изображения расходился между слоями (#133).** Браузер принимает исходник до 25 МиБ для подготовки, GIF без перекодирования ограничен 10 МиБ. Для загружаемого изображения лимит 10 МиБ в shared, порог Multer `MAX_IMAGE_BYTES + 1` и Nginx `11m` учитывают границу парсера и multipart. Проверь ровно лимит и байтом больше на API, multipart через прокси и действительный анимированный GIF. GIF сохраняется байтами, для прочих форматов проверяй прозрачность WebP и JPEG fallback. Старые файлы не требуют перекодирования. `middleware/upload.ts`, `lib/images.ts`, `uploads.test.ts`.
- **Одна картинка передавалась повторно, следующий слайд появлялся пустым (#58, #135).** Проверка модерации предшествует ETag. Для прежнего валидатора проверь 304 доступного файла и 404 файла, связанного только со скрытым материалом. Ранняя загрузка всех слайдов устранила пустой кадр, но со временем стала расходовать трафик на далёкие карточки. Галерея теперь начинает загрузку вблизи экрана и готовит текущий и два соседних слайда. Измеряй начальные запросы и первый свайп на длинной ленте с холодным кэшем. `AssetImage` сообщает конечную ошибку после попытки обычного прокси. Проверь холодный кэш, ограниченную сеть и отказ одного изображения. `app.ts`, `uploads.test.ts`, `measure-feed.mjs`.
- **Прогресс или часть способов ввода отсутствовали в соседних формах (#69, #185, #194).** `useImageDraft` различает подготовку и передачу. Пройди выбор файла, вставку, drag-and-drop, прогресс, ошибку, повтор и удаление превью в посте, комментарии и ЛС. У комментария пределы — два фото и два трека. В #194 процент передачи уже был в hook, а комментарий выводил только статическую надпись. Освобождай object URL. Для временных ID в HTTP-контексте `lib/uuid.ts` поддерживает `getRandomValues` при отсутствии `randomUUID`. `messageImages.test.ts`, `directUpload.test.ts`. Последний проверяет отсутствие устаревших билетов загрузки обычных фото.

Обход JS-обрезки в Firefox и неподвижная подложка в `aero-home.css` закрывают стык. Глобальное снятие теней и непрозрачная заливка шапки портили соседние элементы. Проверяй непрерывный скролл длинной ленты, прозрачную рамку и переход в группу/обратно. Тест геометрии `candidate.spec.ts` может пропустить мерцание между измерениями. Внутренний дефект движка не доказан.
- **Док и мини-плеер двигались вслед за адресной строкой Firefox Android (#5, #166).** Раздельные fixed-слои расходились, объединённый слой смещался целиком, компенсация через `visualViewport`/rAF совпадала лишь в отдельных положениях. Действующий путь использует внутренний скролл окна Bubble, переменные дока и видимую safe area. Проверь весь жест на телефоне, поворот, клавиатуру, последнюю строку, переход в ЛС, возврат к началу ленты и гостевую оболочку. `getPageScroller`, `App.tsx`, `aero-shell.css`, `candidate.spec.ts`.

Проверь длинный → короткий экран и переход через точку прилипания в обе стороны после изменения высоты шапки.
- **Узкая карточка, длинное слово и масштабирование (#114, #180).** В шапке группы, поиске и репосте проверь минимальную ширину flex/grid-потомков и перенос русского текста. Глобальный `overflow: hidden` может срезать меню и фокус. В галерее проверяй переход по краям в обычном режиме и доступ к панорамированию в исходном размере, на iOS также pinch zoom поверх обоев. `candidate.spec.ts` покрывает длинные названия. Отдельный случай посимвольного переноса на iPhone остаётся [открытым](#открытые).

### Общие компоненты и ввод

- **Клавиша переноса отправляла черновик с телефона (#233).** `Composer.tsx`, `CommentInput.tsx` и редактор в `MessagesPage.tsx` оставляют Enter нативным переносом на Android и iOS, включая режим сайта для ПК на iPad. На телефоне пост, комментарий, ответ и ЛС отправляются кнопкой формы. На десктопе Enter отправляет, Shift+Enter переносит строку. Поля поста и комментария растут по содержимому через `useGrowingTextarea`. В комментарии стартовая высота совпадает с кнопкой отправки (44 px), в посте ручная высота сохраняется при редактировании и сбрасывается после публикации. Вставка фото использует тот же `useImageDraft`, что и выбор файла, с предпросмотром и повтором при ошибке. В `candidate.spec.ts` проверяй рост и возврат к исходной высоте, переносы в запросе и опубликованном тексте, ошибку и повтор загрузки. Экранную клавишу проверяй на устройстве.
- **Плавающее меню обрезалось карточкой или диалогом (#69, #156).** Повышение `z-index` внутри области обрезки не освобождало меню. `PostCard` и `CommentInput` используют портал, в `CommunityManagement` список ролей использует popover верхнего слоя. У вложенного диалога обработка `cancel` не должна закрывать родителя. Проверь координаты у последней строки, scroll/resize, Escape, клик вне меню, возврат фокуса и отпускание жеста за границей окна. `useDialogBackdrop`, `candidate.spec.ts`.
- **Перенос CSS или настройки ломал другие поверхности.** Кнопка закрытия галереи и музыкальные окна зависели от базового `.aero-window-control`, стили варианта без базы теряли геометрию. У очереди в Chrome `scrollbar-color` перекрывал оформление `::-webkit-scrollbar`, для поддерживающих псевдоэлемент движков используется `auto`. При удалении вкладки настроек селектор `:last-child` сжимал оставшуюся вкладку. Проверь DOM портала, вычисленные размеры, реальную область клика, Tab/End и оставшиеся вкладки. `ImageGallery`, `MusicPlayer`, `aero-components.css`. У окна несохранённых настроек собственные классы `wallpaper-workshop`: правка только общего диалога не охватывала его blur.
- **Мобильный ввод выглядел рабочим без рабочего жеста.** Нативный `resize: vertical` на Android рисовал ручку, но не менял высоту пальцем. `TextareaResizeHandle` использует Pointer Events с capture. Проверь создание и редактирование, отмену жеста, клавиатуру, минимум высоты и кнопку эмодзи. У `EmojiPicker` и `EmojiText` должны совпадать данные и спрайт. Проверь составную графему, ширину курсора, поиск по-русски, выделение и копирование исходного Unicode, в том числе в сообщениях (#32). `candidate.spec.ts` проверяет touch-resize.

Правка только `maxLength` оставляет прежний контракт модели/сервера. Проверь создание, редактирование, длинную строку без пробелов, свёрнутую карточку и полный текст на отдельной странице. `packages/shared/src/index.ts`, `contentLimits.test.ts`, `PostCard`.

У чекбоксов музыки и «Только друзья» раздельные жёсткие цвета расходились с акцентом. В `emailTemplates.ts` для внешних ресурсов нужны абсолютные URL, текстовая версия и запасной шрифт. Локальный preview подтверждает шаблон, доставку и почтовый клиент проверяют отдельно.

Воспроизведи действие с реальной кнопкой на узком экране. Если симптом исчез, зафиксируй версию и сценарий. ### Оболочка и PWA

- **Старая вкладка не находила ленивый чанк (#96).** После смены сборки прежнего имени файла может больше не быть. `ErrorBoundary.tsx` ограничивает auto-reload распознанной ошибкой модуля, доступной сетью и меткой времени в sessionStorage. У маршрута с выбранным треком `preservePlayback` сохраняет плеер до явного обновления. Проверяй однократное восстановление, постоянный сбой с финальным экраном, обычный сбой API без reload, offline и возврат старой PWA. В тесте дождись повторной навигации. `candidate.spec.ts`.
- **Проверка PWA давала ложную уверенность в связи.** Наличие URL WebSocket в DevTools не доказывает handshake, свежая вкладка не проверяет замену SW. Проверь действующий worker, кадр подключения, polling, отсутствие транспорта в Cache Storage и offline-навигацию. `public/sw.js`, `lib/pwa.ts`, `candidate.spec.ts`. Установку, системный push и доставку на телефоне оценивай отдельным сценарием.

### Стенд и достоверность проверки

- **Автотесты исчерпывали лимит входа перед ручной приёмкой, фото и музыка не работали на втором локальном API.** Проверь ответивший процесс, обычный или тестовый режим, realtime и изолированные MongoDB и S3. Новый экземпляр MongoDB не выделяет новое хранилище файлов. Тестовый режим меняет часть лимитов и телеметрию. Локальный gate требует общего `TEST_GATE_SECRET` уже для подстановки переменных Compose, настройка пароля в админке происходит позднее. [Тестовый доступ](docs/TEST_ACCESS.md).
- **Ошибка теста принималась за дефект приложения.** Проверяй реальный URL, форму ответа, состояние UI и ожидание события. Устаревший smoke ожидал немедленного входа после регистрации, тест загрузки фото — старые ticket-маршруты, тест CMS — превью уже очищенного материала. Для ошибки движка сначала проверь пустую страницу, для медиа — декодирование и Range, для модалки — доступность кнопки под верхним окном. Повтор после тайм-аута учитывай отдельно. Узкий lint и моки не покрывают корневой набор и операции реальной MongoDB.
- **При переносе старого исправления исчезало уже принятое поведение.** Примеры — индикатор аватара, восстановление очереди, проверки доступа и мобильная навигация. Сверяй текущую базу и связанные изменения в истории, разрешая конфликт сохраняй поведение обеих сторон и проверяй пересечение. Старый снимок, статус задачи и номер PR не устанавливают наличие исправления в текущем checkout или выпуске. Ошибка доступа к инструменту сама по себе не подтверждает выход из учётной записи.

## 10. Definition of Done

Перед передачей проверь основной путь через штатный экран или API и затронутых потребителей. Для каждого применимого риска выбери конкретный сценарий: гость/владелец/другой пользователь, старая запись, пустой и большой список, повтор и конкурентная запись, частичный отказ, offline/429, возврат по Back, reload, смена аккаунта. Для исправления ошибки нужна проверка именно исходного симптома. Предпочтителен тест, который падает до правки и проходит после неё. При недоступной автоматизации запиши воспроизводимые шаги, ожидаемый результат и фактическую границу проверки.

| Область | Проверки по риску |
| --- | --- |
| Документация | Сверить команды и утверждения с кодом и историей, относительные ссылки и входящие якоря, diff и новые файлы. Поведенческий прогон нужен для утверждения о поведении, которое нельзя установить чтением. |
| UI / браузер | Все отличающиеся режимы общего потребителя, ширины по сторонам breakpoint, нагруженные состояния и целевые движки. Для TS/TSX — typecheck, для поведения — целевой browser test. Для телефона и слабого устройства указать реальное устройство или пропуск. |
| Функция / API / данные | `npm run typecheck`, `npm run lint`, относящиеся тесты, сборка. Проверить ошибки, права, совместимость и повтор. Для реальных индексов, агрегации, TTL и гонок нужен Mongo-набор. Для пользовательского пути через несколько слоёв — браузер с изолированным реальным API. |
| Realtime / нагрузка | Vitest API и realtime, две сессии, разрыв, истечение JWT, видимость и очистка. `check:tabs` с `BUBBLE_TAB_CHECK_ASSERT=1` и при необходимости expiry. Для нагрузки применяй [критерии оценки регрессии](#9-производительность-и-измерения). |
| Кандидат в выпуск | Typecheck, lint, build, API/realtime, применимые Mongo-наборы, тест gate при затронутом шлюзе, candidate на нужных движках и smoke с реальным API с учётом [известного ограничения](#открытые). Решение о выпуске принимает человек. |

`npm test` запускает Vitest API и realtime. Для Mongo-наборов нужны отдельные `BUBBLE_*_TEST_MONGO_PORT` и иногда дополнительные флаги. Сверяй skip. `npm run check:site` без `BUBBLE_CHECK_URL` проверяет локальную сборку с фикстурами, с URL выбирает другой набор для доступности. `npm run e2e` использует Chromium и реальный API, может переиспользовать процессы и заданный `MONGODB_URI`. Используй только изолированные ресурсы. Тест шлюза — `node --test tools/test-gate/server.test.mjs`. [Команды и условия](docs/TESTING.md).

В отчёте укажи команды или ручные шаги, версию и состояние рабочего дерева, окружение и статус каждого сценария.

- `PASS` — проверка выполнена успешно.
- `FAIL` — проверка выполнена, ожидаемый результат не достигнут.
- `BLOCKED` — проверка невозможна из-за ограничений окружения или внешней зависимости.
- `NOT RUN` — проверка не выполнялась.

Для `FAIL`, `BLOCKED` и `NOT RUN` укажи причину статуса и возможные последствия. Успех набора не даёт `PASS` пропущенному сценарию. Для нагрузки приложи исходный и новый замер и условия. Для дефекта на устройстве укажи движок, ОС, модель, жест и наблюдаемый эффект.

### Правила актуализации

Обновляй карту подсистем при смене владельца данных, маршрута, формы DTO, права или жизненного цикла. Для значимой ошибки найди существующую запись в её подсистеме, зафиксируй симптом, установленную причину, отвергнутый подход, действующий механизм и проверку. Сошлись на файл, тест и известную задачу или ревизию. При замене решения исправь запись на месте. Если есть только сообщение пользователя, сохрани наблюдение и условие следующей проверки в открытых вопросах.

В соответствующем существующем разделе фиксируй значимые архитектурные решения, ранее неизвестные связи подсистем, неудачные технические подходы, особенности браузеров и устройств, подтверждённые способы оптимизации и важные пограничные сценарии. Сохраняй только выводы с долгосрочной практической ценностью. Дополняй существующую запись по теме, хронологию работ оставляй в исходном отчёте.

Вычисляемые параметры и команды сверяй с текущим исходником. Для результатов прогона фиксируй версию и условия в исходном отчёте. Перед передачей проверь ссылки в обе стороны, включая якоря из профильных руководств. [Исторические свидетельства](docs/PROJECT_HANDOFF.md).
