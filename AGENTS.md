# Bubble — обязательные правила

## Перед каждой задачей

- Полностью прочитай [BUBBLE_CONTEXT.md](BUBBLE_CONTEXT.md). Он задаёт технические ограничения Bubble, хранит опыт ошибок и определяет проверки. Эти два файла составляют обязательный рабочий контекст. Профильное руководство открывай по ссылке для затронутой подсистемы.
- Работай в согласованных границах задачи. Сопутствующий рефакторинг, изменение архитектуры и исправление несвязанных ошибок требуют отдельного согласования. О сторонней проблеме сообщи отдельно, укажи последствия и предложи решение. Если без расширения границ задачу выполнить невозможно, обоснуй необходимость и получи согласование до начала дополнительной работы.
- Проверь текущие ветку, HEAD, статус и локальные инструкции в затронутых каталогах. Работай с фактическим содержимым файлов, сохраняй параллельные изменения. В UI-задачах сохраняй `apps/api/uploads/`.
- Проследи изменение от штатной точки входа до данных и всех потребителей общего контракта. Уточни результат для соседних экранов, ролей и старых данных. Переиспользуй существующую реализацию правила.

## Git, GitHub и инфраструктура

Задачи Bubble находятся в [репозитории BubbleFlash/bubble](https://github.com/BubbleFlash/bubble/issues) и на [доске BubbleFlash Project №1](https://github.com/orgs/BubbleFlash/projects/1/views/1). Перед обращением к задаче сверяй `origin` текущего checkout с `https://github.com/BubbleFlash/bubble`.

Для чтения задач через `gh` следуй [инструкции для Codex на Windows](docs/DEVELOPMENT.md#github-cli-bubble). При `401` в песочнице проверь Windows-учётку процесса и, если правила сессии и указания владельца это разрешают, повтори конкретную команду чтения вне песочницы через штатное согласование.

Git, GitHub, CI/CD и серверной инфраструктурой управляют исключительно люди. Правило действует для каждой задачи ИИ.

- Разрешено только чтение Git. Для статуса используй `git --no-optional-locks status --short --branch`. Можно читать историю, ветки, коммиты и diff. При операции, инициированной человеком, можно исправить конфликт непосредственно в файлах. Индексацию, продолжение, завершение или отмену выполняет человек.

- Запрещены любые записи в Git, в том числе `add`, `commit`, `push`, `pull`, `fetch`, `merge`, `rebase`, `checkout`, `switch`, `restore`, `reset`, `stash`, `clean`. Запрет распространяется на индекс, refs, конфигурацию, ветки, теги и управление worktree.
- Запрещено управлять PR, задачами и настройками GitHub, менять GitHub Actions, CI/CD или настройки серверов, запускать доставку, деплой и публикацию. Для штатных локальных проверок используй изолированные данные и сервисы по [DEVELOPMENT.md](docs/DEVELOPMENT.md) и [TESTING.md](docs/TESTING.md).

## Перед передачей

- Примени [Definition of Done](BUBBLE_CONTEXT.md#10-definition-of-done) по риску задачи и укажи статус каждой проверки. Для изменений нагрузки используй [критерии оценки регрессии](BUBBLE_CONTEXT.md#9-производительность-и-измерения).
- Сохрани технический опыт по [правилам актуализации](BUBBLE_CONTEXT.md#правила-актуализации). В отчёте отдели факт от гипотезы. Проверь ссылки, итоговый diff и статус, включая новые файлы.
- Секреты, токены, cookie, учётные и персональные данные исключай из документации, примеров и результатов проверок.
